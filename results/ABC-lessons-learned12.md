### ABC 441-C

コードは[こちら](https://atcoder.jp/contests/abc441/submissions/72564265)

コンテスト中にACできなかった。

酒以外の水 $R = N - K$ 個は最悪選ぶことになる。残り $K$ 個のグラスで最低何個選ぶかが答えである。小さい方から $K$ 個取って全部酒にする。以下 $A$ は小さい方から $K$ 個だけ考え、 $A$ を昇順に並べる。総和が $X$ 未満なら、答えは `-1` である。

コンテスト中に思いついたのは、 $A$ を小さい方から飲んで累積和が $X$ 以上になる最小グラス数である。これは入力例が合うがWAする。カップの液体の量がわからなけばこれがあっているはずだが、題意ではカップの液体の量を知って選ぶことができる。だったら液体の量が多い方が選べばよく、 $A$ を大きい方から飲んで累積和が $X$ 以上になる最小グラス数が答えである。

問題を誤読して落としてしまった。コンテスト中に解けなかった最低diffを更新した。

### ABC 441-E

コードは[こちら](https://atcoder.jp/contests/abc441/submissions/72550761)

セグメント木に載せればいいと分かったが、実装に手こずった上境界値バグをやらかした。

先頭から $i$ 文字取ったときの、 $A$ の個数 - $B$ の個数 を $D_i$ とする。 $D_i$ の累積和を余剰 $C_i$ とする。 $-N \leq C \leq N$ なので、ある $C_i$ を取る $i$ が何種類あるかセグメント木 $T$ に乗せる。添え字を非負にするため、インデックスに $N$ 下駄を履かせて要素数を $2N+1$ にする (要素数が $2N$ だと2 REsする)。

先頭から $i$ 文字を見る。まず $T$ から要素 $C_i$ を1引く。 $i$ 文字まで見て余剰 $C_i$ があり、さらに余剰があるつまり $C_i$ より多い余剰の個数を求める。これはセグメント木に $T[C_i+1,]$ の区間和である。

この区間和をすべての $i$ について求める。Fenwick Treeの方が実行時間が [短い](https://atcoder.jp/contests/abc441/submissions/72574489) 。

### ABC 442-E

コードは[こちら](https://atcoder.jp/contests/abc442/submissions/72724912)

偏角ソートしてセグメント木に乗せる。

回転角をラジアンにするために、左右反転して $X = -X$ とする。さらに $X,Y$ を最大公約数で割って規約にする。そうすると方向 $(X,Y)$ が同じ頂点を、連想配列の同じキー $(X,Y)$ でまとめて扱うことができる。

方向を $atan2(Y,X)$ でソートすると、頂点の順番が決まる。実は `std::atan2` には誤差があるので、doubleでソートすると2 WAsする。long doubleだとACするが、WA例を作れる気がする。C++23の `std::float128_t` を使っても[間に合う](https://atcoder.jp/contests/abc442/submissions/72738234) 。

方向 $D_i=(X_i,Y_i)$ に何個頂点が載っているかをセグメント木 $T$ に乗せる。添え字は方向の順番である。 $A$ が $L$ 番目で、 $B$ が $R$ 番目とする。 $L=R$ なら一点区間 $T[L]$ 、 $L < R$ なら区間和 $T[L,R]$ 、 $L > R$ なら補集合 $N - T[L,R]$ である。

偏角ソートを整数で処理するのが想定解法である。360度にするのがちょっと大変で、最初の実装は大変 [不格好](https://atcoder.jp/contests/abc442/submissions/72745086) である。きれいにすると [こう](https://atcoder.jp/contests/abc442/submissions/72749997) なる。

### ABC 443-C

コードは[こちら](https://atcoder.jp/contests/abc443/submissions/72876325)

優先度キュー $Q$ を使ってイベントをシミュレーションする。

状態として、直前に閲覧を開始した時刻 $P$ 、閲覧中 $B \in \{False, True\}$ を持つ。初期値は $P=0$, $B=True$ とする。

$Q$ の要素は $(T,E)$ つまり時刻 $T$ とイベント $E \in \{Start, Stop\}$ とする。 $E$ は閲覧開始を $Start$ 、閲覧終了を $Stop$ とする。

$Q$ の初期値は以下の通り設定する。

- 勤務開始時に閲覧を開始する $(0, Start)$
- 勤務終了時に閲覧を終了する $(T, Stop)$
- 青木君が通りかかったら閲覧を終了する $(A, Stop)$

$Q$ を取り出すごとに以下の通り処理する。
- $(T, E=Start)$ のとき $B=False$ なら、 $P=T$ , $B=True$ にする
- $(T, E=Start)$ のとき $B=True$ なら、閲覧を続ける。 $B=True$ のままである。
- $(T, E=Stop)$ のとき $B=False$ なら、閲覧しない状態を続ける。 $B=False$ のままである。
- $(T, E=Stop)$ のとき $B=True$ なら、答えに $T - P$ を加算し、 $Q$ に $(T+100, Start)$ を追加する。

この状態遷移なら、勤務終了後に閲覧を開始しても、対応する終了時刻が無いので数えない。明示的にガードするなら [こう](https://atcoder.jp/contests/abc443/submissions/72919632) する。

### ABC 443-D

コードは[こちら](https://atcoder.jp/contests/abc443/submissions/72887153)

最も上にあるマスを固定して、他のマスを近づけて上に寄せていけばいい。

$R_i$ は、現在 $i$ 列目の駒が行 $R$ に置かれていることとする。 `std::set<std::pair<Num,Num>>` 型の $Q$ の要素は $(R_i,i)$ 、つまり $i$ 列目の駒が行 $R_i$ に置かれているとする。

$Q$ の辞書順で先頭の要素 $(R_i,i)$ について、左右の列 $j \in \{i-1, i+1\}$ がもしあれば、行の差を1以下にする。つまり $(R_j,j)$ について、 $|R_i - R_j| \leq 1$ ならそのまま、そうでなければ $R_j = R_i + 1$ にする。このときの移動量を答えに加える。併せて、 $R_j$ を更新する。つまり必要なら $Q$ に $(R_j,j)$ を積みなおし、 $R_j$ を更新する。

$Q$ の積み直しは要素ごとに高々1回なので、 $O(Nlog(N))$ で解ける。

### ABC 443-E

コードは[こちら](https://atcoder.jp/contests/abc443/submissions/72919397)

68分間あったがなすすべがなかった。

到達点として、空きマスだけを移動する方法と、壁マスを破壊しながら進む方法がある。

空きマスだけを移動する方法はBFSというか、下の行からDPすると到達可能なマス $(1,1..N)$ が求まる。これに加えて、マス $(y,x)$ を破壊可能なのは、 $(y+1..N,x)$ が空白の時である。これをDPで考慮する。

列 $x$ について、最下行から連続して $(i..N,x)$ が空白の時に、 $U_x = i$ とする。空白が全くない場合は $i = N+1$ とする。

以下のDPを繰り返す。行 $y$ にいるときに列 $x$ に到達可能であることを $DP[y][x] = 1$ とする。初期値を $DP[][] = 0$, $DP[N][C] = 1$ である。 $DP[y][]$ について求まっているときに、 $y-1$ について以下の通り求める。

- 移動元のマスに移動可能つまり $DP[y][x] = 1$ なら、 $j=x-1,x,x+1$ について以下の更新処理を行う。そうでなければ更新しない。
  - 空白マスに直接移動する。 $DP[y-1][j]$ が空白なら、 $DP[y-1][j]$ を1にする。
  - 壁マスを破壊して移動する。 $U_x \leq y$ なら、 $DP[y-1][j]$ を1にする。併せて、 $U_i = min(U_i, y-1)$ に更新する。コンテスト中にこの処理を思いつかなかった。

$DP[1][]$ が答えである。

### ABC 444-C

コードは[こちら](https://atcoder.jp/contests/abc444/submissions/73119821)

$S = \sum A$ とする。 $L$ は $S$ の約数かつ $max(A)$ 以上の長さしかありえないので、そのような $L$ を総当たりする。

$A$ を昇順にならべておく。長さがちょうど $L$ のりこは無視していい。残りのりこについて、最も長い物と最も短いものを組み合わせ可能か調べる。これは短い方と長い方から尺取り法して、組み合わせた長さの和が全て $L$ かつ、1本だけ残らないことを意味する。

実は約数列挙は要らなかった。というより $3 \times 10^{14}$ の約数列挙がよくTLEせずに済んだ(0.5秒で済む)。

### ABC 444-E

コードは[こちら](https://atcoder.jp/contests/abc444/submissions/73119874)

2秒制限に間に合ってしまった。

$(A_L, A_R)$ が組めて、 $(A_L, A_{R+1})$ を組めないとする。これは $i \in [L+1,R]$ について $|A_i - A_L| \geq D$ であり、 $|A_{R+1} - A_L| < D$ である。便宜上、 $|A_{N+1} - A_L| < D$ は常に成り立つとする。

このような $A_{R+1}$ の最小位置 $R+1$ は、区間最小セグメント木から分かる。 $A$ を座標圧縮し、 $A$ に対応する位置の最小値をセグメント木 $T$ に載せる。開区間 $(A-D, A+D)$ の最小値が $R+1$ である。そのような値が無いときは $N+1$ とする。より具体的には $N..1$ の順に以下の処理を行う。

- $A_i$ について座標圧縮後の $T(A_i-D, A_i+D)$ を求め、 $R_i$ とする
- $T[A_i] = i$ とする

$i=N..1$ について $R_i$ の累積minを取って $C_i$ とする。 $i$ から $C_i$ の直前まで伸ばせると分かるので、 $C_i - i$ を答えに加算する。

セグメント木の処理が重く、1819 ms掛かるがACする。 $A-D, A, A+D$ をすべてセグメント木に載せたのがいけなかった。 $A$ だけ載せれば [458 ms](https://atcoder.jp/contests/abc444/submissions/73123899) なので余裕で間に合う。

公式解説そのまま [尺取り法](https://atcoder.jp/contests/abc444/submissions/73121161) すると413 msで解ける。

### ABC 445-D

コードは[こちら](https://atcoder.jp/contests/abc445/submissions/73334099)

最後に割れた部分は、接合面が接する長さが等しい。これを利用してボトムアップに組み立てれればいい。と思ったが、 `(1,2), (1,5)` と `(1,3), (1,4)` を組み立てる方法が分からない。 `(1,2), (1,3)` だと詰むのだが、この詰みを回避する方法が分からない。

重大な制約を見落としていた。「もう一方のピースは手に持ったままにする」の意味を、コンテスト中には理解できなかった。置くピースの高さか幅の少なくとも一方は分割前と一致するのを、延々と繰り返したものが、最終的な結果である。よって最初に置いたピースは、高さが $H$ と一致するか、幅が $W$ と一致するはずである。これを $(1,1)$ に置き、残った長方形に残ったピースを置く。これらも同様に繰り返すことができる。

まとめると、以下の処理を $N$ 回繰り返せば、ピースの配置の一つが求まる。原点を $(0,0)$ とするので、出力する答えにはそれぞれ1を足す。また縦方向を $Y$ , 横方向を $X$ とする(問題文と逆)。

- これからピースを置くべき空白領域について、始点 $(SY,SX) = (0,0)$ 、幅と高さ $(H,W)$ で初期化する。
- あるピース $i$ があり、高さが $Y_i = H$ 、幅は $X_i$ とする。このピースを始点が左上角になるよう配置する。そうすると始点は $(SY, SX+X_i)$ になり、領域は $(H, W-X_i)$ になる。以後ピース $i$ は置かない。
- あるピース $i$ があり、高さが $Y_i$ 、幅は $X_i = W$ とする。このピースを始点が左上角になるよう配置する。そうすると始点は $(SY+Y_i, SX)$ になり、領域は $(H-Y_i, W)$ になる。同じピースは一回限り配置するので、上記と同時にはやらない。

ある高さ $Y$ のピースと、ある幅 $X$ のピースをそれぞれ連想配列で管理する。ピースを除いたら、両方の連想配列から除く。一方からだけ除くとWAする。

入力例2を可視化すれば、外側のピースから順番に剥がすと気づいた可能性がある。E問題の方針が立っているので早く戻りたい気持ちで焦りすぎた。

### ABC 445-E

コードは[こちら](https://atcoder.jp/contests/abc445/submissions/73338520)

方針はすぐ立ったが、実装方法が分からなかった。方針はすぐ立ったのが仇になって、F問題を読み忘れてしまう。

高速素因数分解ができれば、答えは求まる。しかし私がコンテスト中に取った方法では2秒に収まらない。

$i=2..10^{7}$ の素因数分解が分かっているものとする。つまり素数 $P$ と指数 $C$ があり、 $i$ = $\prod P_j^{C_j}$ と分解済とする。

テストケースについて、全数のLCMは、 $LCM = \prod P^{max(C)}$ である。ここで $max(C)$ は、すべての $A$ についての、素因数 $P$ の係数の最大値である。

$A_i = \prod P_j^{C_j}$ を除いた場合、どれだけ素因数が減るか考える。 $P_j^{D_j}$ だけ減るとする。 $C_j < max(C)$ なら除く影響はないので $D_j = 0$ である。 $C_j = max(C)$ のとき、 $P$ の二番目に多い素因数が $T$ 個なら(なければ $T=0$ とする) 、 $D_j = C_j - T$ として $P^{D_j}$ だけ減る。よって $LCM / \prod P_j^{D_j}$ が答えである。

公式解説は、線形篩を用いて、 $A$ の最小の素因数を求めておく。そうすれば $A$ の素因数分解をその場でやっても2秒に間に合う。ライブラリ化して `-O2` 最適化すると0.2秒で済む。


Fenwick Tree 2本の場合、累積和を上手く分解する。0-based indexingで考える。

- 素の値 $V[0..N]$ を、差分系列 $D[0..N]$ にする。 $D[0] = V[0]$ , $D[i] = V[i] - V[i-1]$ である
- 素の値は差分から、 $V[i] = \sum_{j=0}^i D[i]$ である。これをFenwick Tree $TD$ で管理する。ここでFenwick Treeは半開区間 $TD[i] = [0, i)$ の和を返すものとする。
- 累積和の元になるの差分系列として、 $U[i] = (i + 1) \times D[i]$ を作る。累積和の都合上、添え字が一つずれている。これをFenwick Tree $TU$ で管理する

半開区間 $[0,i)$ の和 $S[i]$ は、 $\sum_{j=0}^{i-1} = \sum_{j=0}^{i-1} ((i + 1) \times U[i]) - \sum_{j=0}^{i-1} D[i] = i \times TU[i] - TD[i]$ である。累積和の都合上、添え字が一つずれている。よって半開区間 $[L,R)$ の和は、 $S[R] - S[L]$ である。

半開区間 $[L,R)$ に一律 $V$ を加算する処理を、以下のように行う。いもす法である。

- $TD[L]$ に $V$ を足す
- $TD[R]$ に $-V$ を足す
- $TU[L]$ に $LV$ を足す
- $TU[R]$ に $-RV$ を足す

```cpp
void solve(std::istream& is, std::ostream& os) {
    Num n, q;
    is >> n >> q;

    atcoder::fenwick_tree<Num> diffs(n+1);
    atcoder::fenwick_tree<Num> accums(n+1);

    Vec va(n);
    for(auto&& a : va) {
        is >> a;
    }

    diffs.add(0, va.at(0));
    for(Num i{1}; i<n; ++i) {
        const auto d = va.at(i) - va.at(i-1);
        diffs.add(i, d);
        accums.add(i, d * i);
    }

    while(q-- > 0) {
        Num cmd;
        is >> cmd;

        if (cmd == 1) {
            Num l, r;
            Num v;
            is >> l >> r >> v;
            --l;
            diffs.add(l, v);
            diffs.add(r, -v);
            accums.add(l, l * v);
            accums.add(r, -r * v);
        } else if (cmd == 2) {
            Num l, r;
            is >> l >> r;
            --l;
            const auto ans = (r * diffs.sum(0, r) - accums.sum(0, r)) - (l * diffs.sum(0, l) - accums.sum(0, l));
            os << ans << "\n";
        }
    }
}
```

愚直にシミュレーションする。 $i=0..N$ について、以下を操作 $i$ を呼ぶ。

- $v=1..M$ のうち、初期 $A$ において出現回数が0回の $v$ の集合 $S_0$ を昇順に $A$ の末尾に付ける
- $v=1..M$ のうち、初期 $A$ において出現回数が0または1回の $v$ の集合 $S_1$ を昇順に $A$ の末尾に付ける
- 一般的には、 $v=1..M$ のうち、初期 $A$ において出現回数が0以上 $i$ 回以下の $v$ の集合 $S_i$ を昇順に $A$ の末尾に付ける

$S_{i+1}$ は $S_i$ と同じか、 $S_i$ に要素を追加する(初期 $A$ において出現回数が $i+1$ 回の $v$ の集合)かどちらかなので、差分更新できる。よって $S_i$ を追加した時の要素数をもとに、クエリに答えることができる。

- 便宜上、 $L_{-1} = |A| = N$ とする
- $X \leq L_{-1}$ なら、答えは $A_X$ である
- 操作 $i$ の時点で、 $A$ の長さは $L_i = |A| + \sum_{j=0}^{i} |S_i|$ である。 $L_{i-1} < X \leq L_{i}$ なら、答えは $S_i$ の $X - L_{i-1} + 1$ 番目である。
- 操作 $M$ が終わると $L_M$ が確定する。以後 $1..M$ を1回ずつ末尾に加えるループになっている。 $X > L_M$ なら、答えは $X - L_M$ を $M$ で割った余りに1足したものである。

$S_i$ から $S_{i+1}$ をコピーで作って $S_{0..M}$ を網羅するとTLEする。 $S_i$ と $S_{i+1}$ が同じときにエイリアシングしてもやはり 3 TLEsする。クエリを先読みして、 $X$ の昇順に尺取り法の要領で実装する。併せて $S$ を一つのPBDS (Policy Based Data Structures)として保持し、順序付き集合かつ昇順に $X$ 番目と答えられるようにすると間にあう。

$S_i$ の加算操作は高々 $\sqrt{N}$ 回なので $O(M \sqrt{N})$ なのは見切ったが、それ以後の実装があまりにも遅すぎたし、クエリ先読みは思いつかなかった。

クエリ先読みを思いつけば、PBDSではなくFenwick treeで [解ける](https://atcoder.jp/contests/abc449/submissions/74170275) 。

- $L = l$ な区間を $S,T$ に加える。つまり新たに左端が掛かった区間を加える。
- $R = r$ な区間を $U$ に加える。つまり新たに右端が掛かった区間を加える。
- $R < l$ な区間を $S,T$ から除く。つまり右端が外れた区間を除く。
- $r < L$ な区間を $U$ から除く。つまり左端が外れた区間を除く。

- 人数が $R$ のチームに属すことはできるが、人数が $L$ のチームに属すことはできない人数は $|U|$ 人である
- 人数が $L,R$ のどちらのチームに属すことができる人数は $C$ 人である

- $L$ を左端とする布のうち、右端の最小値をセグメント木 $T[L]$ で持つ。布が無ければ $\infty$ とする。
- $L$ を左端とする布のうち、右端の重複無し集合を $U[L]$ で持つ。
- $R$ を右端とする布のうち、左端の重複無し集合を $V[R]$ で持つ。
- 布の集合を $[L,R]$ を何個持つかの連想配列 $C[L,R]$ で持つ

各クエリについて、以下の順序で解く。

1. $U[L]$ または $V[R]$ の少なくともどちらか一方が空なら、左端または右端をちょうどそろえることはできない。答えは `No` である。
2. $C[L,R] \leq 2$ なら、 $[L,R]$ の布を二枚使って答えは `Yes` である。
3. $C[L,R] = 1 \land T[L+1,R] \leq R$ なら、 $[L,R]$ の布を一枚使い、 $[L,R]$ に包含される布をもう一枚使い答えは `Yes` である。
4. $C[L,R] = 1$ で上記以外なら、 $[L,R]$ の布と他の布を重ねるとはみ出すので、答えは `No` である。
5. $C[L,R] = 0$ なら、 $[L,R1]$ の布と $[L1,R]$ の布を重ねる。詳細は下記。

左端が $L$ で、 $L < R1 < R$ つまり右側にはみ出さない最も長い布を選ぶ。これは $U[L]$ に `std::set::lower_bound` を使うと求まる。右端が $R$ で、 $L < L1 < R$ つまり左にはみ出さない最も長い布を $V[R]$ から選ぶ。このような布を選ぶことができ、かつ長さが足りる $R1 - L + R - L1 \geq R - L$ なら答えは `Yes` である。そうでなければ答えは `No` である。

### ABC 459-E

コードは[こちら](https://atcoder.jp/contests/abc459/submissions/76077968)

C,D問題でドカ遅れを見せたが、E問題で巻き返した。

組み合わせを前処理できないが、それさえ気を付ければ単にDFSである。

DFS再帰関数は、頂点 $i$ についてタプル $(C_i, R_i)$ を返すとする。 $C_i$ はその頂点についての組み合わせで、有効な組み合わせがなければ0を返す。 $R_i$ はその頂点についてリスが回収しなかったアメの数で、アメが不足しているなら負の値を返す。コンテスト中は部分木の $C_i$ の和をタプルに含めたが [不要](https://atcoder.jp/contests/abc459/submissions/76093458) である。

葉ノードについて考える。 $C_i$ 個のアメから $D_i$ 個のアメを選ぶ組み合わせは $C_i \choose D_i$ 通りである。残ったアメは $R_i = C_i - D_i$ 個である。

$C$ が大きいので、 $C_i \choose D_i$ を高速に求める関数を、以下のように定義する。乗除算回数は $2 \sum_j D_j$ 回なので十分高速である。

- $C_i < 0 \lor D_i < 0 \lor C_i < D_i$ なら0通り
- そうでなければ $(\prod_{j=C_i-D_i+1}^{C_i} j) / (\prod_{1}^{D_i} j)$ 通り。除算をまとめて一回にすべきだが、毎回やってもTLEしない。

葉ノード以外のノード $i$ について考える。子ノードを $j$ とする。 $R_j < 0$ なら解を満たす組み合わせは無いので $C_i = 0, R_i = -1$ である。そうでなければ、ノード $i$ のリスは $P_i = C_i + \sum_j {R_j}$ 個のアメから $D_i$ 個の選び方がある。よって $C_i = {P_i \choose D_i} \prod_j {C_j}$ , $R_i = C_i + (\sum_j R_j) - D_i$ である。ただし $R_i < 0$ なら $C_i = 0$ とする。

DFSを頂点1から始めて $C_1$ を出力する。

公式解説にある通り、除算を [前計算する](https://atcoder.jp/contests/abc459/submissions/76098314) と少し速くなる。

当たりが尽きた後の最初のはずれの直前まで行動できる。当たりの累積和を $A_i = \sum_{k=1}^{i} k$ とする。外れの累積和を $B_j = \sum_{k=1}^{j} k$ とする。 $i$ を固定した時、 $B_j - B_i \leq A_i$ を満たす最小の $j$ について $min(j-1,N)$ が答えである。これを二分探索すると上手くいかない。 $i$ が増えるほど当たりの数 $A_i$ は広義単調増加であり、従って $j$ もやはり広義単調増加である。よって尺取り法で解くのが正解である。この方法は公式解説2と同様である。

公式解説1を言い直す。最初に $K$ この袋を取り、 $j$ 個の当たりがあれば、 $k-j \geq 0$ 個のはずれがある。この先当たりがあれが前進し、はずれは $j$ 個まで許容されるので、結局 $k - j + j = k$ 個目ちょうどのはずれがある場所まで進める。これを二分探索で解くと [こう](https://atcoder.jp/contests/abc469/submissions/78175442) なる。

- $A,B$ それぞれについて、人 $i$ の出現回数 $C_i$ をあらかじめ数える。 $C_i$ 出現回数のヒストグラムを、サイズ $M+1$ のFenwick Tree $T[0..M]$ に載せる。

### ABC 471-E

コードは[こちら](https://atcoder.jp/contests/abc471/submissions/78419344)

$N = 1$ の時の1ペナが惜しい。

$K = 1$ なら、単に二乗和を答える。オーバーフローしないよう、二乗の時点で ModInt を使う。

$K > 1$ なら、係数の寄与を考える。 $A + B + C = A^2 + B^2 + C^2 + A(B+C) + B(A+C) + C(A+B)$ である。これを一般化する。

二乗成分 ${A_i}^2$ は、 ${N} \choose {K}$ 通りの組み合わせ、 $K$ 個の係数を選ぶので、1係数当たり $C_{NK} = {{N} \choose {K}} /N$ である。よって $C_{NK} \times \sum_i {A_i}^2$ である。これを答えに加える。

異なる二数の積の成分 $AB$ は、 $A_i$ を固定し、 $B \in A \setminus A_i$ の寄与に注目する。 ${N-1} \choose {K-1}$ 通りの組み合わせ、 $K-1$ 個の係数を選ぶので、1係数当たり $C_{N1K1} = {{N-1} \choose {K-1}}/(N-1)$ である。よって $A_i$ に寄与を掛けた物  $A_i \times C_{N1K1} \times ((\sum_j A_j) - A_i)$ を答えに加える。累積和をあらかじめ求めて計算量を減らす。ここで $N = 1$ だとREするので、 $K = 1, K \leq N = 1$ を別扱いした。

組み合わせは一度求めればいいが、コンテスト中はループ内に入れて $N$ 回求めてしまった。C++なら十分速いし、おそらく最適化が効いてループ外に出してくれたのかもしれない。念のため [書き直した](https://atcoder.jp/contests/abc471/submissions/78450362) 。

```cpp
std::string concat(std::vector<std::string>& ss) {
    std::sort(
        ss.begin(), ss.end(),
        [](const auto& lhs, const auto& rhs) {
            return lhs + rhs > rhs + lhs;
        });
    std::string t;
    for(const auto& s : ss) {
        t += s;
    }

    std::ranges::reverse(t);
    while(!t.empty()) {
        if (t.back() == '0') {
            t.pop_back();
        } else {
            break;
        }
    }
    std::ranges::reverse(t);

    if (t.empty()) {
        const std::string z {"0"};
        return z;
    }

    return t;
}
```

$T = 0$ なら解無しなので `No` である。 $D_i > 0$ な石の重みを一律 $W_T$ とし、 $D_i < 0$ な石の重みを一律 $W_A$  とする。 $T W_T > A W_A$ を満たせばよく、 $W_T / W_A > A / T$ なので、例えば $W_T = 2A + 1, W_A = T$ にすれば解を満たす。

公式解説にある通り、 $W_T = 10^{18}, W_A = 1$ でよい。

```cpp
#include <ext/pb_ds/tree_policy.hpp>

using namespace __gnu_pbds;
using TreeElement = std::pair<Num,Num>;
using ordered_multiset = tree<
    TreeElement,
    null_type, std::less_equal<TreeElement>,
    rb_tree_tag,
    tree_order_statistics_node_update>;

void solve(std::istream& is, std::ostream& os) {
    constexpr Num k = 3;
    Num n {0};
    is >> n;

    ordered_multiset mset;
    for(Num i{0}; i<n; ++i) {
        Num a;
        is >> a;
        mset.insert(std::make_pair(a,i));
        if (i >= 2) {
            os << mset.find_by_order(i-k+1)->first << "\n";
        }
    }
}
```

### ABC 476-D

方針はすぐに立ったが、デバッグだ泥沼だった。

$A$, $B$ は昇順にソート済とする。 $A$ についての累積和 $C_i = \sum_{j=1}^{i} A_i$ をあらかじめ求める。

$B$ を $T = 0..M$ 個買うこと決め打ちして、それぞれの答えの最大値が答えである。Greedyで解ける。まず残額 $R = X + YK$, 残紙幣 $W = Y$ で初期化する。

$T = 0$ のときは、 $C_i \leq R$ を満たす最大の $i$ が、買えるドリンクの数である。

$T = 1$ のときは、紙幣が $S = \lceil B_{T} / K \rceil$ 枚必要である。 $S > W$ なら買えないので、探索を打ち切る。買えるなら残額を $R - B_{T}$ だけ減らし、残紙幣を $W - S$ にする。その上で、 $C_i \leq R$ を満たす最大の $i$ が、買えるドリンクの数である。このとき答えは $T + i$ である。

$T > 1$ についても同様に逐次更新する。
