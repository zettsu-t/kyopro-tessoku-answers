### ABC 481-E

コードは[こちら](https://atcoder.jp/contests/abc481/submissions/80339114)

偏角ソートだとは分かったが、そこから55分掛かった。自作偏角ソートライブラリにリンクを張った。

最初に外積を使って偏角ソートして、原点からみて同じ向きの星を束ねる。ソート済の向きを $A$ とする。ある向き $A_s$ からちょうど正反対の向き $A_t$ にある星までの範囲 $[A_s,A_t)$ にある星の数を数える。ここで大苦戦した。

`atan2` の返り値が $[-\pi, \pi]$ だと分からなかった。角度を `std::float128_t` で持って、角度でソーティングした結果を `std::lower_bound` で探索すると 8WAs する。ここまで 34分、追加で21分使うことになる。角度を `std::float128_t` で持つこと自体は間違いではなく、正しく実装すれば [ACする](https://atcoder.jp/contests/abc481/submissions/80370521) 。どの相異なる2個の星についても、それらと原点が一直線上に並ぶことはないという制約を見落としていた。

偏角ソートとの結果を二周する。ある角度 $A_s$ から見て外積が正となる最大範囲を `std::ranges::partition_point(std::views::iota(i, i + len), pred)` で求めると、 $A_t$ が分かる。 `pred` は $A_s$ との外積が正になるという術語である。直線に割った領域にある星の数は $D = t - s$ である。よって $max(D, N - D)$ で既知の答えの最大値を更新する。 $len$ は頂点数ではなく偏角の種類の数である。

公式解説2の方法はなぜか上手くいかない。

### ABC 481-F

コードは[こちら](https://atcoder.jp/contests/abc481/submissions/80359245)

頂点1から頂点 $u$ までのパス長を $D[u]$ とする。スコアを $S[u]$ について、 $D[u] < D[v]$ なら $S[u] < S[v]$ である。よってBFSで頂点1からの距離が等しい頂点についてスコアの大小を気にする。距離が短い頂点のスコアは、一度決まったら以後は更新することはない。

スコアの定義は、頂点 $u$ から直接頂点 $v$ に移動したとして、辺 $(u,v)$ の重みを $W_{u,v}$ として $S[v] = 10 \times S[u] + W_{u,v}$ である。これを任意精度整数で直接保存するとMLEするので、 $mod 998244353$ で保存する。スコアが低い順にBFSすれば、スコアそのものを記録する必要はなく $mod$ で十分である。

頂点1からの距離が $i$ の頂点集合を $S[i]$ とする。 $S[i]$ はスコア順に広義単調現象(非減少)でソートされているとする。実装上は、距離とスコアが等しい頂点集合をタプル $(dist,score,us)$ で持つ。 $us$ の要素 $u$ から直接遷移した頂点 $v$ について、タプルは $(dist+1, 10score+W_{u,v}, u)$ である。遷移元のスコアが等しい遷移先頂点について、タプルをソートし、スコアが未定の頂点にだけ遷移する。頂点1からの距離が等しい頂点をまとめて処理することでスコア順を維持できる。

コンテスト中はおおよその感触をつかんだものの実装方法が分からず、ダイクストラ法にスコアを直接乗せてMLEした。パスグラフを考えればスコアの桁数が $O(N^2)$ になるのだから当然である。もう使わないスコアを $mod 998244353$ だけで保存するよう切り替えようとして失敗した。翌朝BFS解法を思いついて解いた。Trieという言葉がちらっと見えたが、実質的には同じことをしている。

公式解説1のように、優先度キューを使った実装ができそうだとは思ったが、解説を読むまで実装方法が分からなかった。こう [実装](https://atcoder.jp/contests/abc481/submissions/80380069) する。

### ABC 482-D

コードは[こちら](https://atcoder.jp/contests/abc482/submissions/80512517)

入力例1が親切である。

人 $1$ と人 $N$ は端まで動くしかないので、全員の幅が答えである。 $N=1$ を見過ごしたが結果的に0が返る。

それ以外の人 $i$ は、以下のパターンを考える。時間はすべて、答えの倍で考える。

初手を右に動いた場合、以下のどちらかの最大時間が掛かる。

1. $T1$ : 右に動き続けて、人 $N$ をゾンビにする。 $A_N - A_i$ の時間が掛かる
2. $T2$ : ゾンビ $i+1$ は左に動き続けて人 $1$ をゾンビにする。

同様に初手を左に動いた場合、以下のどちらかの最大時間が掛かる。

1. $T3$ : 左に動き続けて、人 $1$ をゾンビにする。 $A_i - A_1$ の時間が掛かる
2. $T4$ : ゾンビ $i-1$ は右に動き続けて人 $N$ をゾンビにする。

$min(max(T1,T2), max(T3,T4))$ が答えである。公式解説通りである。

### ABC 482-E

コードは[こちら](https://atcoder.jp/contests/abc482/submissions/80535333)

コンテスト終了直前に解法が浮かんだが、間に合わなかった。

木の直径 $D$ を求める。直径の両端にある二頂点 $U,V$ の組から、距離の和が $D$ で、 $U,V$ までの距離が $\lfloor D/2 \rfloor$ となる頂点 $C$ が木の中心である。 $C$ が二点あるときはどちらか一つを採用する。

$C$ を根とする木を考える。色が同じ二頂点 $U,V$ までの距離の和が $D$ である、つまりLCAが $C$ なら題意を満たす。直径の定義から、 $U,V$ は葉に限定してよい。 $C$ の隣の子を根とする部分木をすべて列挙して、各部分木について、深さ($C$ からの距離)と色の組に対する頂点数を数える。これらを合計したものを $T$ にする。

ある部分木について、深さ $S$ 、色 $C$ の頂点数が $T_{S,C}$ 個あったとする。その部分木以外について、深さ $D-S$ 、色 $C$ の頂点数が $T_{D-S,C}$ 個あったとする。これらの組み合わせ $T_{S,C} \times T_{D-S,C}$ を答えに加える。

最後に答えを半分にしたものを出力する。 [再実装](https://atcoder.jp/contests/abc482/submissions/80543083)したが、実装に時間が掛かりすぎる。

### ABC 483-C

コードは[こちら](https://atcoder.jp/contests/abc483/submissions/80666441)

問題文をシミュレーションする。データ構造を以下の通り定める。

- 各投票者の投票 $V_i$ 。要素は $V_i[0]$ を第一希望、 $V_i[1]$ を第二希望とする配列である。
- 各候補者を第一希望とする投票者 $A_i$ 。要素は投票者の番号。この配列の長さを誤って $M$ にしてREが返る。もったいないペナルティである。
- 各候補者の、第一希望としての得票 $C_i$

これを順序付き集合 $S$ `std::set<std::pair<Num,Num>>` に載せて順位をつける。要素は $(C_i,-i)$ である、こうすると $S$ に `rbegin()->second` は、最多得票かつ番号が最小の候補者なので、答えが求まる。

候補者 $i = 1..N$ について、以下の通りいなかったことにする。

- $S$ から $i = (C_i,-i)$ を除く
- $a \in A_i$ の投票者について、第二候補を加える。 $S$ の $(V_i[1], D)$ を $(V_i[1], D+1)$ に置き換える。置き換える前の要素がなければ、要素は純増である。
- $S$ の最大要素を求めて、 $i$ の答えとして出力する。
- 第二候補を除く。つまり $S$ の $(V_i[1], D+1)$ を $(V_i[1], D)$ に置き換える。 $D=0$ なら要素は純減である。
- $S$ から $i = (C_i,-i)$ に加える

セグメント木の方がイテレータ操作が無くて [実装](https://atcoder.jp/contests/abc483/submissions/80709370) しやすいし、実行も速い。

### ABC 483-D

コードは[こちら](https://atcoder.jp/contests/abc483/submissions/80674430)

方針はすぐ立ったが、実装に手間取った。

ロボットの移動先を累積する $P_0 = 0$ , $P_i = \sum_{j=0}^i A_i$ とする。区間最大セグメント木 $S$ と区間最小セグメント木 $T$ に、 $P_{0..N}$ を載せる。

高々一回とあるので、 $S[0..N] - T[0..N] + 1$ が答えの最小値である。ここで $A_i$ の符号を反転させる。

$A_i$ を反転させると、 $[0..(i-1)]$ の最大最小値は変わらず、 $[i..N]$ の最大最長値は $-2A_i$ 増える。よって最小値は $B = min(S[0..i-1], S[i..n] - 2A_i)$ に、最大値は $C = max(S[0..i-1], S[i..n] - 2A_i)$ になる。答えの候補は、 $C - B + 1$ であるので、答えを更新する。

公式解説3を [実装](https://atcoder.jp/contests/abc483/submissions/80709118) したが、後ろからの累積和が難しい。公式解説と少し実装を変えたが、0をminmaxに [含める](https://atcoder.jp/contests/abc483/submissions/80709172) 必要がある。

### ABC 483-E

コードは[こちら](https://atcoder.jp/contests/abc483/submissions/80701677)

TLEになった。4秒制限なので間に合うと思ったらだめだった。

解き方が全くわからないので公式解説を読んで実装したら `std::map` で 3829 ms 、 `std::unordered_map` で 2298 ms [だった](https://atcoder.jp/contests/abc483/submissions/80701705) 。ハッシュは32 bitで(5x6ビット)で十分である。

ちなみにカスタムハッシュは [このよう](https://cpprefjp.github.io/reference/functional/hash.html) に作る。

```c++
using Str = std::array<uint8_t, 8>;
constexpr uint8_t Mark = 0;

struct str_hash {
    auto operator() (const Str& str) const {
        size_t result = 0;
        for(Num i {5}; i>=0; --i) {
            result = (result << 5) + str.at(i);
        }
        return result;
    }
};

using Table = std::unordered_map<Str, Num, str_hash, std::equal_to<>>;
```

### ABC 484-C

コードは[こちら](https://atcoder.jp/contests/abc484/submissions/80831481)

全く方針が立たず、今日はダメかと思った。F問題の方がやさしく見える。条件を順番に絞っていく。

- $A,B$ が完全に一致するなら、答えは `Yes` である。
- $A,B$ それぞれをソートして、一致しなければ要素があわないので答えは `No` である。
- 左から見て $A_L \ne B_L (L=1..N)$ となる最小の $L$ を見つける。右から見て $A_R \ne B_R (R=N..1)$ となる最大の $R$ を見つける。 $L = R$ なら $A,B$ の違いは一か所であり、答えは `No` である。
- $A[L,R]$ を一回右巡回シフトした後で、 $A = B$ なら答えは `Yes` である。 `std::rotate` を使うと楽に実装できる。
- $A[L,R]$ を一回左巡回シフトした後で、 $A = B$ なら答えは `Yes` である。
- 以上のどれでもなければ、答えは `No` である。

### ABC 484-D

コードは[こちら](https://atcoder.jp/contests/abc484/submissions/80836722)

簡単に言うと、同じ数字の列 `1111` に `1` を混ぜても、答えの種類は増えない。 $i=1..N$ について、 $A_i$ を移動する。

- $a = A_i$ について、 $A_{i-1} = A_i$ なら、 $A_{i-1}$ について数えた場合から答えの種類は増えない。なぜなら $A_i$ が連続する値の最左でなければ、 `1111` の最左を移動するのも、最左以外を移動するのも、得られる結果は同じだからである。
- $A_{j=1..i-1} = a$ を満たす $A_j$ が存在するなら、 $A_j$ の前に挿入するのと、 $A_j$ の後に挿入するのと、結果は変わらない。要するにこのような $j$ の数だけ答えが減る。

値が $a$ であるような $A$ の位置の集合 $P[a]$ をあらかじめ求めておく。 $i=1..N$ について以下の処理を行う。最初の答えは $A$ 自身のみの1とする。

- $A_{i-1} = A_i$ なら何もしない。
- $A_{i-1} \ne A_i = a$ なら、値が $a$ であるような $A$ の位置で $j < i, A_j = a$ を満たす $j$ の個数 $C$ を求める。これは $P[a]$ を二分探索すると求まる。答えに $i - 1 - C$ を足す。

これらの和が答えである。公式解説と同じである。

### ABC 484-E

コードは[こちら](https://atcoder.jp/contests/abc484/submissions/80848410)

一瞬悩んだが、よく考えたらいつもの累積和である。PBDSを使うと実装が簡単で、299 msec なので実行も速い。

累積和 $C_i = \sum_{j=1}^i A_i$ とする。これを多重集合 $S$ に載せる。

```c++
using ordered_multiset = tree<
    TreeElement,
    null_type, std::less_equal<TreeElement>,
    rb_tree_tag,
    tree_order_statistics_node_update>;
```

答えの初期値を0として、 $i=1..N$ について以下のように求めて答えに加える。便宜上 $C_0 = 0$ とする。

- $S$ における、 $C_{i-1} + L$ の順位を $S$ とする。これは $L$ 未満の要素数である。
- $S$ における、 $C_{i-1} + R + 1$ の順位を $T$ とする。これは $R$ 以下の要素数である。
- $T - S$ を答えに足す。つまり $R$ 以下の要素数から $L$ 未満の要素数を引く。
- $S$ から $C_i$ を除く。

この方法は公式解説2と同じである。

### ABC 484-F

コードは[こちら](https://atcoder.jp/contests/abc484/submissions/80845093)

E問題より先に解いた。見た瞬間、ランダマイズが使えると思った。

値 $V=0..max(A) \leq 10^6$ に対して、 $10^{18}$ 以下の乱数を割り当てる。これを $R[V]$ とする。

セグメント木に、 $(Wild,Sum,Max)$ を載せる。単一ノードについては、以下の通り定義する。

- $Wild$ は $V = -1$ なら $true$ 、 $V \geq 0$ なら $false$ である。
- $Sum$ は $Wild = true$ なら $0$ 、そうでなければ $R[V]$ である。
- $Max$ は $Wild = true$ なら $0$ 、そうでなければ $R[V]$ である。

ノードの合成は以下の通りとする。

- $Wild$ はすべての子ノードが $true$ なら $true$ 、それ以外は $false$ である。
- $Sum$ は $Wild = true$ なら $0$ 、そうでなければ子ノードの和である。
- $Max$ は $Wild = true$ なら $0$ 、そうでなければ子ノードの最大値である。

クエリに答える。クエリ1は、セグメント木の要素 $i$ を、上記の要領で置き換える。クエリ2は区間和 $(W,S,M)$ を得る。
- $W$ が $true$ なら答えは `Yes` である。
- $W$ が $false$ かつ、 $S$ が $M$ で割り切れるなら、答えは `Yes` である。
- それ以外は `No` である。

素直に区間最大最小セグメント木で解けるらしい。乱数は要らなかった。
