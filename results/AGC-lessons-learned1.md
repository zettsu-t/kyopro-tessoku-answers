### AGC 002-A

コードは[こちら](https://atcoder.jp/contests/agc002/submissions/46054808)

丁寧に場合分けする

- $0 < a \leq b$ なら積は正
- $a \leq b < 0$ なら、a以上b以下の整数の数 $b-a+1$ が偶数個なら積は正、奇数個なら積は負
- 上記以外、つまり $a \leq 0 \leq b$ なら積は0

### AGC 002-B

コードは[こちら](https://atcoder.jp/contests/agc002/submissions/51937786)

丁寧にシミュレーションする

不確定なのは赤白どちらのボールを渡すかであって、それぞれの箱に何個ボールがあるかは決定的である。よって操作 `1..M` を順番に実行して、箱に赤いボールがあるかもしれない、もしくはそうではない(箱が空か、白いボールしかない)かを伝搬する。

- 箱 $X$ に赤いボールがあるかもしれないなら、操作後の箱  $Y$ も赤いボールがあるかもしれない

- 操作後に箱  $X$ が空でなければ、箱  $X$ に赤いボールがあるかどうかは変わらない

### AGC 002-C

コードは[こちら](https://atcoder.jp/contests/agc002/submissions/57607446)

逆から考える。

短いロープから順に結合して、最後に $N$ 本のロープを結合したものを考える。

隣り合う2本ロープを結合して長さ $L$ 以上になるものがなければ、結合して $L$ 以上の2本のロープをほどくことができないので、答えは `Impossible` である。

そうでなければ答えは `Possible` である。隣り合う2本ロープを結合したときの長さが $L$ 以上になるようなロープの組 $(i,i+1)$ を、結合する候補として優先度キューに載せる。

キューから最も長さが短いロープの組 $(p,p+1)$ を取り出す。これはロープ $[l,..p]$ と $[p+1,..r]$ を結合することを意味する。
- $(p,p+1)$ を結合済なら何もしない
- $(p,p+1)$ を未結合なら結合する。ロープの組は一まとまりの区間 $[l,..p,p+1,..r]$ を成すので、左右の区間と結合することを候補としてキューに載せる。
  - $l > 1$ なら $l-1$ を含む区間 $[a,l-1]$ , $[l,r]$ を結合するように、候補 $(l-1,l)$ をキューに載せる。
  - $r < N$ なら $r+1$ を含む区間 $[l,r]$ , $[r+1,b]$, を結合するように候補 $(r,r+1)$ をキューに載せる

ロープを結合済かどうかは、union-find木で管理する。あるロープにどのロープを結合したかは、ロープの代表元に `std::set<Num>` で持たせて、結合しているロープの最小値と最大値と長さが分かる。ロープを結合したとき、要素数の少ない方を要素数の多い方にマージして、結合したロープの代表元に関連付ける。

これを $N-1$ 回繰り返すと $(p,p+1)$ の結合順が求まるので、逆順にしてほどく順番が答えである。

公式解説を読むと、優先度キューを使うまでもなく、隣り合う2本ロープを結合したときの長さが $L$ 以上になるようなロープの組 $(i,i+1)$ から左右に結合すればよかった。

### AGC 003-B

コードは[こちら](https://atcoder.jp/contests/agc003/submissions/57259585)

GreedyではWAすると思ったのだが。

DPが正解である。 $(i,i), (i+1,i+1)$ と $(i,i+1), (i,i+1)$ でペアの数は同じである。よって $(i,i+1)$ を1つ作るか作らないどうかでDPする。

$DP[i][0]$ を $i$ まで見た時 $(i,i+1)$ を作らないときのペアの最大数、 $DP[i][1]$ を $i$ まで見た時 $(i,i+1)$ を一つ作るペアの最大数とする。初期値 $DP[0][] = 0$ とする。また $(i,i+1)$ をペアにしないときの $A$ を $A0$  、 $(i,i+1)$ をペアにしたときの $A1$ とし、 $A0 = A1 = A$ で初期化する。

$DP[i][0]$ は $max(DP[i-1][0] + \lfloor A0_i / 2 \rfloor, DP[i-1][1] + \lfloor A1_i / 2 \rfloor)$ である。

$DP[i][1]$ は $max(DP[i-1][0] + 1 + \lfloor (A0_i - 1) / 2 \rfloor, DP[i-1][1] + 1 + \lfloor (A1_i - 1) / 2 \rfloor)$ である。ただし $(i,i+1)$ をペアにできないときを考え、前者は $A0_i < 1 \lor A0_{i+1} < 1$ なら0、後者は $A1_i < 1 \lor A1_{i+1} < 1$ ならで0ある。

上記の操作 $i$ について終わったら組んだペアの分だけ $A0_i,A0_{i+1},A1_i,A1_{i+1}$ を減らす。上記の操作が $i=1..(N-1)$ について終わったら $N$ だけでペアを組み、 $max(DP[i][0] + \lfloor A0_N / 2 \rfloor, DP[i][1] + \lfloor A1_N / 2 \rfloor)$ が答えである。

公式解説はgreedyである。視点が違った。実装は [こちら](https://atcoder.jp/contests/agc003/submissions/57259748) 。

### AGC 003-C

### AGC 004-B

コードは[こちら](https://atcoder.jp/contests/agc004/submissions/60831464)

最終的に色 $i$ のスライムを飼うとする。魔法を $j$ 回唱えた結果色 $i$ になったなら、元の色は $(N + i - j) mod N$ である。

魔法を最大 $k$ 回唱えられるとする。 $0 \leq K \leq N$ である。それぞれのスライムに唱える魔法は $K$ 回以下の任意の回数である。そこで以下のDPを考える。

- 魔法を $i$ 回唱えてスライムを色 $j$ にするための、元のスライムの最小のコストを $DP[i][j]$ と置く
- 魔法を $0$ 回唱えたとき、 $DP[0][j] = a_j$ である
- 魔法を $i+1$ 回唱えたとき、 $DP[i+1][j] = min(DP[i][j], a_{j + N - i})$ である。右辺の左側を選んだ時、魔法を $i$ 以下しか唱えたら止めにすることを意味する。
- 魔法を $i$ 回唱えたときのコストは $ix + \sum_j DP[i][j]$ である。この値の、すべての $i$ についての最小値が答えである。

### AGC 004-C

コードは[こちら](https://atcoder.jp/contests/agc004/submissions/61438420)

構築問題(constructive problem)は難しいが、ABC 387-Eでも出るのでARC/AGCに出場するなら解けなければならない。

ヒントになるのはヒューズROM (One Time Programmable ROM) の構造である。ワード線とビット線の交点を溶断するかどうかで情報を保持する。同じ要領でこの問題を解く。つまりワード線とビット線を一通り塗ってから、要らない部分を塗らなかったことにする。

両端を除く偶数行、偶数列を赤く塗る。両端を除く奇数行、奇数列を青く塗る。最左列をすべて赤く塗り、最右列を青く塗る。これで赤いマス、青いマスは一つの連結成分を構成する。これを初期配置にする。最上行と最下行以外のマスは、赤か青かどちらか一方で塗られている。

このままだと入力した紫色のマスと不一致になる。入力は紫色だが、初期配置では赤か青かどちらか一方でしか塗られていない場合を考える。このときは足りないほうの色を塗ればよい。新たにマスを塗るので、赤、青それぞれのマスが一つの連結成分であることに変わりはない。

入力は紫色ではないが、初期配置では赤と青の両方で塗られている場合を考える。このとき行の塗り方を維持し、列で塗った色を塗らなかったことにする。列で塗った色に関して、このマスを塗らなかったとしても、このマスの上下の行は最左列(赤)か最右列(青)で連結するので、赤、青それぞれのマスが一つの連結成分であることに変わりはない。

最外周に紫のマスは無いので、これをすべてのマスについて繰り返すと答えが求まる。

この方法は公式解説と同じである。列のことは考えずに初期配置から塗り足す分、上記より公式解説の方がわかりやすい。

### AGC 004-D

どうしても答えが合わない。

首都からすべての町を距離の近い順を、テレポートを逆向きにしたグラフで探索する。 $K=1$ なら、首都までの距離1でない頂点の数である。特に首都も含む。

そうでなければ、首都から自己ループがなければ追加する。それ以後は、首都を起点に、首都までの距離の短い順に探索する。町 $v$ が首都からの距離 $K$ 以内なら何もしない。距離 $K+1$ になったら町 $v$ から首都への直行路を1本追加する。追加したら町 $v$ から首都への距離は1になる(0ではない)。いずれにしても $v$ にテレポートできてまだ訪れていない町を探索する。

公式解説通りのはずだが、なぜか 23 WAs が返ってくる。

### AGC 005-A

コードは[こちら](https://atcoder.jp/contests/agc005/submissions/51938689)

括弧

`S,T` を `(,)` 、さらに `1,-1` だと思えば典型問題である。括弧の対応が取れないつまり累積して0未満なら削除できず、そうでないところの区間を削除できる。

Rubyで再帰正規表現を使うと部分点が獲れる。


### AGC 005-B

コードは[こちら](https://atcoder.jp/contests/agc005/submissions/60832278)

数 $i=1..N$ が最小値として何回数えられるか求める。

1の位置を $P_1$ として、1が最小値となる区間は、左端が $[1,P_1]$ 、右端が $[P_1,N]$ の区間である。

2の位置を $P_2$ として、2が最小値となる区間は、番兵を $0,N+1$ として、 $0 < P_2 < P_1$ なら 左端が $(0,P_2]$ 、右端が $[P_2,P_1)$ の区間である。 $P_1 < P_2$ なら 左端が $(P_1,P_2]$ 、右端が $[P_2,N+1)$ の区間である。

この操作を一般化する。既に出現した数字の集合を $S = [0,N+1]$ で初期化する。数値 $i$ について、 $S$ において $i$ を超えない最大値を $L$ 、 $i$ を超える最小値を $R$ とすると、区間の数は $(P_i - L)(R - P_i)$ である。 $i$ の答えに対する寄与 $i(P_i - L)(R - P_i)$ を答えに足して、 $S$ に $P_i$ を加える。

これを $i=1..N$ について繰り返すと答えになる。

### AGC 005-C

コードは[こちら](https://atcoder.jp/contests/agc005/submissions/61275155)

木の直径、つまり二頂点間の距離の最大値 $D = max(A)$ を求める。直径となる両頂点を横一線に張って、その枝を張ることを考える。この直線状は両端を含めて、左端から数えた頂点 $i=0..D$ について距離は $L_i = max(i,D-i)$ になる。これらを一つずつ $A$ から除く。除くことができないつまり $L_i$ が $A$ に含まれないなら答えは `Impossible` である。

残った $A$ について、直線から枝を張る。枝の距離は少なくとも $H = 1 + \lceil D/2 \rceil$ なので、これを下回る $A$ の要素があれば、答えは `Impossible` である。そうでなければ枝の長さが1になる場所から枝を生やせばよく、答えは `Possible` である。同じ頂点から複数の枝を生やしても構わない。

### AGC 008-D

コードは[こちら](https://atcoder.jp/contests/agc008/submissions/61319525)

実は区間スケジューリング問題。単なるgreedyだと上手くいかない。

以下0-based indexingを読み替える。答えの長さを $L = N^2$ とする。数字の置き場所を $P[0..(L-1)]$ 、 $P$ の候補を集合 $S = 0..(L-1)$ と置く。

最初に入力の値を固定し、置き場所 $P[x_i] = i$ とし、 $S$ から $x$ を除く。

次に $P$ に左から順に(添え字の昇順に)数字を詰める。このやり方は区間スケジューリングそのもので、 $(x_i,i)$ の昇順に、 $S$ から小さい順に $i$ を $x_i$ 要素取り出して $P$ に詰める。途中で $x_i$ より大きくなったら手詰まりなので `No` を返す。

次に $P$ に右から順に(添え字の降順に)数字を詰める。 $(x_i,N-i)$ の昇順に、 $S$ から大きい順に $i$ を $N-x_i-1$ 要素取り出して $P$ に詰める。途中で $x_i$ より小さくなったら手詰まりなので `No` を返す。

手詰まりにならなければ $P$ の内容が確定するので、1-based indexingにして出力する。

上記の区間を $(x_i-i,i)$ つまりここから連続して並べればぎりぎり間に合う最大の添え字にしたらWAした。

### AGC 009-A

コードは[こちら](https://atcoder.jp/contests/agc009/submissions/46740046)

非対称

ボタン $N$ の影響は $A_{N-1},A_{N}$ に及ぶが、ボタン $N-1$ の影響は $A_{N}$ には及ばない。なのでボタン $N..1$ の順に何回押すか決めればよい。

ボタン $N$ を押す回数は $(N - (A_N \quad mod \quad B_n)) \quad mod \quad B_N$ である。ボタン $N..(i+1)$ までを $d$ 回押したとして、ボタン $i$ を押す回数は $(N - ((d + A_i) \quad mod \quad B_i)) \quad mod \quad B_i$ である。

### AGC 009-B

コードは[こちら](https://atcoder.jp/contests/agc009/submissions/60491083)

トーナメントの決勝を根、初戦を葉として、根から葉までの深さを距離と定義する。題意を満たすつまりトーナメント木全体の深さを最小にするには、深い部分木を浅い頂点につなげればよい。これはDFSで求まる。

今DFSで注目している人を $p$ として、初期値を $p=1$ として以下の通り探索する。

- $p$ に直接負けた人の集合を $S$ とする。 $l \in S$ それぞれについて、部分木の高さを $H_l$ とする。
- $H_i$ を降順に並べる。 $i = 1..|S|$ について、 $min(i + H_i)$ が、 $p$ に関する部分木で深さ最小のものである。

- $N$ が偶数の時、 $i=1..(N/2)$ について $(2i,2i-1)$ を入れ替え、 $i=2..(1+N/2)$ について $(2i,2i-1)$ を入れ替える回数は、二項係数のそのものである。偶数回入れ替えるのは入れ替えないのと同じ(0回入れ替えるのと同じ)なので、二項係数の偶奇だけ求めればいい。

この方法は公式解説と同じである。

当初の着眼点が悪く時間が掛かってしまった。 $N$ が偶数なら左半分と右半分に対称性がある(端からの距離が等しい添え字の値を足すと $N+1$ になる)とか、 $N = 2^i$ なら左半分は $2^{i-1}$ と同じだとか、確かにそうなのだが解法にはつながらない。実験コードを素早く書けることは重要である。

```cpp
void visit_dfs(Num l, Num r, Vec& v) {
    if ((l + 1) == r) {
        std::swap(v.at(l), v.at(r));
        return;
    }

    visit_dfs(l, r-1, v);
    visit_dfs(l+1, r, v);
    return;
}

void solve(std::istream& is, std::ostream& os) {
    Num n {0};
    is >> n;

    Vec ns(n);
    std::iota(ns.begin(), ns.end(), 1LL);
    visit_dfs(0, n-1, ns);
    print_oneline(ns, os);

    Vec inv(n);
    for(Num i{0}; i<n; ++i) {
        inv.at(ns.at(i)-1) = i+1;
    }
    print_oneline(inv, os);
}
```

前処理として $A$ は $modK$ を取った値とする。

緩和問題として、 $AmodK$ のすべての要素はそれぞれ異なるとする。 $A$ を昇順に並べる。 $A_i < A_{i+1}$ なので、これらの距離は $K - (A_{i+1} - A_i)$ になる。 $(A_N, A_1)$ 間の距離も考慮して、差が最も広いところを除いて他の組み合わせ $(A_i, A_{i+1})$ を採用すればいい。

### AGC 068-B

コードは[こちら](https://atcoder.jp/contests/agc068/submissions/58295200)

正確な時間をはかりそこねたが、自力ACまで3時間を切ったと思う。ヒントは解くまで見ていない。

$A$ が同じ値 $a$ を共有する集合 $a= A_{a1}, A_{a2} ...$ について、 $a$ をキーとして添え字の昇順の集合 $P_a = [a1, a2, ...]$ と、 $P_a$ を一回左シフトした集合 $Q_a = [a2, ..., a1]$ を求める(集合の要素が1個以下なら $P_a$ と同じにする)。

初期値として $S$ は $N$ 個の `0` 、 $T$ は $N$ 個の `1` を考える。最初に $S,T$ に $N$ 個の要素 $S_1, T_1$ を追加し、 $A_1$ に値を持ってくる。 $a = A_1$ として $P_{a,j} = A_1$ を満たすある $j$ があって、位置 $Q_{a,j}$ から持ってくればよい。これは $S_1$ の $Q_{a,1}$ と等しい要素を `1` に、それ以外を `0` にすると実現できる。 $T_1$ はすべて `0` にする。以後、 $[1..N] \setminus Q_{a,1}$ について同じ操作を行う。このようにすれば、 $P_{a,j}$ をサイクルにすることができる。

上記を一般化して、 $i = 1..N$ 回目の操作を規定する。初期値として、追加する添え字の集合を $R = [1..N]$ で初期化する。

$S$ に $N+1-i$ 個の要素 $S_i$ を追加し、 $T$ に $N+1-i$ 個の `0` を追加して、 $A_i$ に値を持ってくる。 $a = A_i$ として $P_{a,j} = A_i$ を満たすある $j$ があって、位置 $Q_{a,j}$ から持ってくればよい。これは $R$ の $Q_{a,1}$ と等しい要素を `1` に、それ以外を `0` にすると実現できる。より正確には、 $R$ を昇順に並べた要素について、 $j$ 番目の要素が $Q_{a,1}$ なら $S_i$ の $j$ 番目を `1` にし、それ以外の $S_i$ の要素を `0` にする。この後、 $R$ から $Q_{a,1}$ を取り除く。

$|S| = N + \sum_{i=1}^{N} i = N + (N+1)N/2$ なので、 $S$ の長さは制約を満たす。

公式解説と全く同じ解き方だと思う。
